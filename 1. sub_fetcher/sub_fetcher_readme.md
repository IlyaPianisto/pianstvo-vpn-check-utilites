# sub_fetcher — парсер VPN-подписок

Скрипт запрашивает ссылку на подписку, маскируясь под официальный клиент Happ, и сохраняет полученное содержимое соответствующе: либо в готовый JSON-конфиг Xray, либо в список ссылок `vless://` / `hysteria2://`.

---

Если подписка зашифрована (например happ://crypt4), можно воспользоваться/скачать [happ-decryptor (ссылка на GitHub на том же сайте)](https://leeeet.dev/happ-decryptor/)

---
## Что умеет

- Эмулирует клиентское приложение заголовками `User-Agent`, `x-hwid`, `x-device-os`, `x-ver-os`, `x-device-model`.
- При первом запуске автоматически создаёт `.env` со случайными HWID, User-Agent и версией Windows при первом запуске.
- Сначала пробует локальный SOCKS5-прокси `socks5://127.0.0.1:10808`, если запущен VPN через клиент с XRAY-TUN, то запрос пойдёт через него. При ошибке автоматически повторяет запрос напрямую (без прокси).
- Игнорирует системные переменные `HTTP_PROXY` / `HTTPS_PROXY` — используется только явно заданный прокси или прямое подключение.
- Автоматически определяет формат ответа:
  - Base64-строка — декодируется;
  - JSON с `outbounds` и полем `protocol` — считается Xray-конфигом;
  - JSON с `outbounds` без `protocol` — считается sing-box-подобным конфигом;
  - JSON-массив конфигов — сохраняется как есть;
  - любой другой JSON — сохраняется как generic-JSON;
  - обычный текст — построчно сохраняется как список ссылок.
- Читает заголовок `profile-title` (в том числе в виде `base64:...`) и использует его как имя файла.
- Не перезаписывает существующие результаты: добавляет `-2`, `-3` и т.д.

---

## Требования

- Python 3.10+.
- Установленные зависимости из корневого `requirements.txt` (`httpx`, `socksio`, `python-dotenv`).
- Доступ к серверу подписки.
- SOCKS5-прокси на `127.0.0.1:10808` желателен, но не обязателен: если его нет или запрос через него не удался, скрипт повторит запрос напрямую. Порт зашит в коде (`PROXY`), изменить его через `.env` нельзя.
- Если подписка доступна только изнутри VPN, поднимите VPN/прокси, который слушает порт `10808`.

Установка зависимостей (из корня проекта):

```powershell
pip install -r requirements.txt
```

## Запуск

```powershell
cd "1. sub_fetcher"
python sub_fetcher.py
```

Скрипт попросит ссылку:

```
=== Парсер конфигураций XRAY-JSON ===
Введи ссылку на подписку: https://example.com/sub/abcdef
```

Пустую строку вводить нельзя — скрипт завершится с сообщением «Ссылка не введена!».

> Запускайте именно из папки `1. sub_fetcher`: `.env` и папка `configs/` создаются относительно текущего каталога.

## Результат

Всё складывается в `configs/` рядом с текущим рабочим каталогом:

| Что получили | Имя файла |
|---|---|
| JSON-конфиг, есть `profile-title` | `configs/<title>_config.json` |
| JSON-конфиг, заголовка нет | `configs/vpn_config.json` |
| Список ссылок, есть `profile-title` | `configs/<title>_links.txt` |
| Список ссылок, заголовка нет | `configs/vpn_links.txt` |

`<title>` очищается до безопасного имени: остаются буквы (включая кириллицу), цифры, `_` и `-`, длина ограничена 50 символами.

Если файл с таким именем уже существует, будет создан `...-2.json`, `...-3.json` и т.д.

Во время работы в консоль выводятся способ подключения (прокси или напрямую), статус HTTP, размер ответа, найденные заголовки (`profile-title`, `subscription-userinfo`, `content-type`), факт декодирования Base64 и итоговый путь к файлу.

## Файл `.env`

Создаётся автоматически при первом запуске в текущем каталоге:

```env
HWID=<случайный UUID>

# Эмуляция клиента
USER_AGENT=Happ/4.3.0/Windows/<случайное число>
DEVICE_OS=Windows
VER_OS=10.0.22631
DEVICE_MODEL=Desktop
```

- `HWID` — идентификатор устройства.
- `USER_AGENT` — строка клиента Happ.
- `VER_OS` — случайно выбранная сборка Windows из списка в коде. 

При необходимости, значения можно менять вручную; повторно они не генерируются, пока файл существует.

`.env` попадает в `.gitignore` — не выкладывайте его в публичный репозиторий.

## Обработка ошибок

- Ошибка через прокси не прерывает работу: выводится причина и выполняется попытка прямого подключения.
- Если не удались обе попытки (таймаут 15 секунд, 5 секунд на соединение, HTTP-ошибка), выводится `ERROR: ошибка при прямом запросе подписки: ...`, скрипт завершается без создания файла.
- Если ответ не удалось разобрать как JSON, он сохраняется как список строк — по одной ссылке на строку.
- Заголовок `profile-title`, который не удалось декодировать из Base64, просто игнорируется.
